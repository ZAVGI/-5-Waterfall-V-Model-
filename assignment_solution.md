# Решение заданий по теме Waterfall / V-Model и BPMN

## Задание №1. План разработки корпоративной ИС

**Выбранная методология:** **Waterfall (каскадная модель)**.

Ниже приведен план из **7 этапов** с целью, ключевыми задачами, примером бизнес-процесса (верхнеуровнево) и входными/выходными артефактами.

| Этап | Цель и ключевые задачи | Пример бизнес-процесса (IDEF0 / BPMN Level 1) | Входные артефакты | Выходные артефакты |
|---|---|---|---|---|
| **1. Инициация и обследование (AS-IS)** | Понять контекст компании и границы проекта. Задачи: определить стейкхолдеров, зафиксировать проблемы текущего процесса, выделить KPI проекта. | **IDEF0 A-0 «Управление заказами (AS-IS)»**: вход — заявки клиентов; управление — регламенты; механизм — отдел продаж/склад; выход — исполненные/просроченные заказы. | Устав проекта, оргструктура, действующие регламенты, интервью | Отчет обследования, карта AS-IS, реестр проблем и рисков |
| **2. Сбор и анализ требований** | Сформировать полные бизнес-, функциональные и нефункциональные требования. Задачи: интервью, приоритизация (Must/Should/Could), критерии приемки. | **BPMN Level 1 «Прием и обработка заказа»**: Клиент → Менеджер → Склад → Бухгалтерия. | Отчет AS-IS, цели бизнеса, интервью с пользователями | SRS/ТЗ, backlog требований, матрица трассируемости |
| **3. Системное и архитектурное проектирование** | Определить архитектуру решения и интеграции. Задачи: выбрать архитектурный стиль, описать подсистемы, интерфейсы и модель данных. | **IDEF0 A0 «Управление запасами (TO-BE)»**: вход — остатки/заказы; управление — политики пополнения; выход — план закупок. | SRS/ТЗ, IT-ограничения, требования ИБ | SAD (архитектурный документ), ER-диаграмма, API-контракты |
| **4. Детальное проектирование** | Подготовить проектные спецификации для разработки. Задачи: детализировать модули, UI-формы, бизнес-правила, сценарии исключений. | **BPMN Level 1 «Согласование закупки»**: Инициатор → Руководитель → Финансы → Закупки. | SAD, стандарты кодирования/UX, регламенты | DDS/LLD, прототипы UI, спецификации модулей |
| **5. Реализация (разработка и интеграция)** | Реализовать функциональность в коде и выполнить интеграцию компонентов. Задачи: разработка модулей, code review, сборки CI. | **BPMN Level 1 «Автоматическое формирование счета»**: событие заказа → расчет → генерация счета → отправка клиенту. | DDS/LLD, API-контракты, тестовые данные | Исходный код, сборки, техническая документация разработчика |
| **6. Тестирование и верификация** | Подтвердить соответствие системы требованиям. Задачи: модульное, интеграционное, системное, приемочное тестирование; дефект-менеджмент. | **IDEF0 «Контроль качества релиза»**: вход — билд; управление — тест-план; механизм — QA; выход — отчет о качестве/дефекты. | Сборка, тест-план, SRS/критерии приемки | Test Report, дефект-лист, протокол UAT |
| **7. Внедрение и сопровождение** | Ввести систему в эксплуатацию и обеспечить стабильную работу. ## Задание №2. Свойства бизнес-процессов и нотация BPMN

### 1) Пять свойств бизнес-процессов

| Свойство | Описание | Пример процесса |
|---|---|---|
| **Детерминированность** | Шаги выполняются в фиксированной логике при одинаковых условиях. | Согласование договора по установленному маршруту. |
| **Цикличность** | Процесс повторяется с заданной периодичностью. | Ежемесячное закрытие бухгалтерского периода. |
| **Автоматизация** | Полностью или частично выполняется ИС без ручных действий. | Ночная рассылка уведомлений о просроченной дебиторке. |
| **Измеримость** | Для процесса заданы KPI: время, стоимость, качество, процент ошибок. | Обработка заявки клиента с KPI «не более 4 часов». |
| **Вариативность (ветвление)** | Путь выполнения зависит от условий/правил. | Выбор сценария закупки по сумме и категории затрат. |

### 2) Выбранный процесс для BPMN-описания

**Процесс:** «Согласование договора».

#### BPMN Level 1 (текстовая схема)

**Pool: Компания**

1. **Start Event** — получен проект договора.  
2. **Task (Менеджер):** зарегистрировать договор в системе.  
3. **Task (Юрист):** правовая экспертиза.  
4. **Exclusive Gateway:** есть замечания?  
   - **Да** → **Task (Менеджер):** доработать договор с контрагентом → возврат к задаче юриста.  
   - **Нет** → далее.  
5. **Task (Финансы):** проверка финансовых условий.  
6. **Exclusive Gateway:** сумма договора > лимита?  
   - **Да** → **Task (Директор):** финальное утверждение.  
   - **Нет** → пропуск этапа директора.  
7. **Task (Менеджер):** отправить договор на подписание.  
8. **End Event** — договор согласован и передан на подписание.

#### Пояснение элементов BPMN

- **Start/End Event** — фиксируют начало и завершение процесса.  
- **Task** — атомарные работы исполнителей (роль/подразделение).  
- **Exclusive Gateway (XOR)** — точка выбора одного из альтернативных путей.  
- **Sequence Flow** — направляет поток работ между шагами.  

#### Входные и выходные артефакты процесса

- **Вход:** проект договора, карточка контрагента, лимиты полномочий, шаблон договора.  
- **Выход:** согласованный договор, протокол замечаний, журнал согласования (audit trail).

## Краткий вывод

- Для корпоративной ИС по Waterfall ключевое значение имеет строгая последовательность этапов и формализация артефактов на каждом шаге.  
- BPMN Level 1 позволяет прозрачно описать роли, точки ветвления и результат процесса, что упрощает автоматизацию и контроль KPI.
